# SwitchCast 帮助与排障手册

> 遇到问题时，先看下面的速查表定位章节，再按「现象 → 可能原因 → 排查步骤」逐步处理。
> 所有步骤都是普通用户可以直接操作的，不涉及任何代码或技术内容。

## 1. 安装与启动

### 1.1 打开应用被 macOS 拦截（提示"无法打开""已损坏"）

**现象**：双击 SwitchCast 后弹出"无法打开""已损坏，应移到废纸篓"或"无法验证开发者"。

**可能原因**：SwitchCast 是免费开源项目，没有购买 Apple 开发者公证。macOS 对从网上下载且未经公证的应用会默认拦截，这是正常现象，不代表应用有问题。

**排查步骤**：

1. 在「访达 → 应用程序」中找到 SwitchCast，**右键点击（或按住 Control 键点击）→ 选择「打开」**，在弹窗中再次点击「打开」。
2. 如果右键打开仍然失败，打开「终端」应用，输入以下命令后回车：
   ```
   xattr -cr /Applications/SwitchCast.app
   ```
   这条命令的作用是移除 macOS 给下载文件打的"隔离标记"，执行后直接双击打开即可。
3. 如果提示"已移到废纸篓"：先从废纸篓把 SwitchCast 拖回「应用程序」文件夹，再执行第 2 步的命令。

> 小技巧：确认你下载的安装包来自 [GitHub Releases](https://github.com/Isaacocu/switchcast/releases)。本项目没有任何官网，任何收费下载站都是假冒的。

### 1.2 下载了错误架构的版本

**现象**：应用打开后闪退、提示不受支持，或运行异常缓慢。

**可能原因**：Mac 分 Apple 芯片（M1/M2/M3/M4）和 Intel 芯片两种，需要下载对应版本的安装包。

**排查步骤**：

1. 点击屏幕左上角苹果图标 →「关于本机」，查看"芯片"或"处理器"一栏。
2. 显示 Apple M 开头 → 下载 `arm64` 版本；显示 Intel → 下载 `x64` 版本。
3. 到 [Releases 页面](https://github.com/Isaacocu/switchcast/releases) 重新下载正确版本，覆盖安装。

### 1.3 在 DMG 里直接运行，没有拖入"应用程序"

**现象**：应用能打开，但设置保存失败、更新失败，或出现奇怪的报错。

**可能原因**：双击 DMG 安装包后，看到的是一个临时磁盘窗口。如果直接在这个窗口里运行应用，应用处于"只读"状态，无法写入文件，也无法自我更新。

**排查步骤**：

1. 打开 DMG 后，把 SwitchCast 图标**拖到「应用程序（Applications）」文件夹图标上**。
2. 弹出 DMG 磁盘，从「应用程序」文件夹启动 SwitchCast。

## 2. 系统权限

SwitchCast 需要两项系统权限才能工作：**摄像头权限**（用来读取采集卡的画面，采集卡在系统里被识别为"摄像头"）和**麦克风权限**（用来读取采集卡的声音）。

### 2.1 首次授权

**现象**：第一次选择设备或开始投屏时，系统弹出"SwitchCast 想要访问摄像头/麦克风"的提示。

**排查步骤**：

1. 弹窗出现时，直接点击「允许」。
2. 如果不小心点了「不允许」，可以手动开启：打开「系统设置 → 隐私与安全性 → 摄像头」（麦克风同理），找到 SwitchCast，把开关打开，然后重启应用。

### 2.2 权限弹窗被忽略后，再也不弹了

**现象**：之前误点了"不允许"或忽略了弹窗，现在应用直接报错，也不再出现授权提示。

**可能原因**：macOS 只会弹一次授权提示，被忽略后不会主动再弹。

**排查步骤**：

1. 打开「系统设置 → 隐私与安全性 → 摄像头」。
2. 如果列表里有 SwitchCast，直接打开它的开关。
3. 如果列表里没有 SwitchCast，选中应用条目后用左下角的「−」号移除（或先确认应用已关闭），然后重新打开 SwitchCast 并开始投屏，系统会再次弹出授权提示。
4. 麦克风权限按同样方式检查一遍。

### 2.3 应用更新后，权限突然失效

**现象**：更新 SwitchCast 之后，原来正常的画面/声音突然需要重新授权。

**可能原因**：SwitchCast 使用临时签名（ad-hoc 签名）发布，每次更新后签名指纹会变化，macOS 会把它当成"一个新应用"，要求重新授权。这是正常现象，不是故障。

**排查步骤**：

1. 按 [2.1](#21-首次授权) 的步骤重新授予摄像头和麦克风权限。
2. 重启应用。

## 3. 采集卡与画面问题

这是最常见的问题区域，请耐心按顺序排查。

### 3.1 采集卡不出现在设备列表

**现象**：打开 SwitchCast 后，视频设备列表是空的，或看不到你的采集卡。

**可能原因**：USB 连接不稳、供电不足，或设备被其他软件占用。

**排查步骤**：

1. **换一个 USB 口**，优先使用电脑机身上的接口，不要用扩展坞/USB Hub（Hub 供电不足时，设备可能完全识别不到）。
2. 拔下采集卡，等 3 秒再插上，听到系统提示音后再打开应用。
3. 在 SwitchCast 中点击「**刷新设备**」按钮重新扫描。
4. 确认没有其他软件正在占用采集卡（如 OBS、Zoom、相机类应用），退出它们后再刷新。
5. 注意 USB 接口规格：USB 2.0 的接口（常见于老式 Hub）带宽不足，可能带不动 1080p60，请尽量插在 USB 3.0 及以上的接口上。
6. 以上都无效时，重启电脑一次，重新插拔采集卡。

### 3.2 开始投屏报错 "Could not start video source"

**现象**：设备列表里能看到采集卡，但点击「开始投屏」后报错 `Could not start video source`（错误代码 START_FAILED）。

**可能原因**：这个报错的意思是"系统拒绝了这次采集启动"，按可能性从高到低有五种情况，请**按顺序排查**。

**① 采集卡被其他应用占用（最常见）**

1. 退出 OBS、Zoom、腾讯会议、系统「相机」等一切可能使用摄像头的软件。
2. 检查是否开了第二个 SwitchCast 窗口（包括后台残留），只保留一个。
3. 退出后重新点击「开始投屏」。
4. 仍失败时，重启电脑——这能彻底清掉系统摄像头服务里的残留占用。

**② 采集卡没有收到 Switch 的画面信号**

1. 检查 HDMI 线两端是否插紧：一头接 Switch 底座的 HDMI 输出口，一头接采集卡的输入口（注意不要插到采集卡的"输出/OUT"口）。
2. 确认 Switch 已开机，并且**放在底座上**。Switch 只有在底座模式下才输出 HDMI 画面；从底座取出变成掌机模式后，输出会立即中断。
3. 确认底座已接通电源（底座的供电线必须插上，否则不输出画面）。
4. 可以用系统自带的「照片亭（Photo Booth）」或 OBS 打开采集卡验证：如果这些软件也出不了画面，说明问题在采集卡/线材/Switch 一侧，而不是 SwitchCast。

**③ 分辨率或帧率超出了采集卡的能力**

1. 打开 SwitchCast「设置」，把分辨率改为 **1280x720**、帧率改为 **30**。
2. 再次点击「开始投屏」。
3. 如果成功了，说明之前设置的分辨率/帧率超出了采集卡支持的范围，可以逐档往上调试出它的上限。

**④ 摄像头权限未授予**

1. 按 [第 2 章](#2-系统权限) 检查并授予摄像头权限，然后重试。

**⑤ 拔插采集卡后设备信息过期**

1. 如果排查过程中拔插过采集卡，应用里记住的旧设备信息会失效。
2. 点击「**刷新设备**」，重新选择采集卡，再开始投屏。

### 3.3 有画面但黑屏/蓝屏/雪花

**现象**：投屏已启动，但画面区域是黑的、蓝的或满屏雪花。

**可能原因**：采集卡工作了，但没有收到有效的 HDMI 信号。

**排查步骤**：

1. 确认 Switch 已开机且在底座上（掌机模式不输出画面）。
2. 换一根 HDMI 线试试——线材损坏是黑屏/雪花的常见原因。
3. 检查中间是否接了其他设备（如 HDMI 分配器、切换器）。**个别带 HDCP 版权保护的中转设备会导致黑屏**：Switch 本身不带 HDCP 保护，但如果信号经过了带 HDCP 的中转设备，采集卡可能拒绝接收画面，请把中转设备从链路中拿掉，让 Switch 直连采集卡。
4. 点「停止投屏」后重新「开始投屏」。

> 名词解释：HDCP 是一种视频版权加密，启用时信号会被加密，普通采集卡无法显示。

### 3.4 画面卡顿/帧率低/延迟高

**现象**：画面能动但明显不流畅，操作有明显的滞后感。

**可能原因**：USB 带宽被其他设备分摊，或电脑性能压力大。

**排查步骤**：

1. 把采集卡直接插到电脑机身的 USB 3.0 口，不要和移动硬盘、摄像头等设备共用同一个 Hub。
2. 在「设置」中适当降低分辨率和帧率（如 1280x720 / 30fps）观察是否改善。
3. 在「设置」中切换**采集模式**试试：自动 / 原生加速（仅 macOS，延迟更低）/ WebView，不同采集卡在不同模式下的表现可能差别很大。
4. 关闭其他占用性能的软件（浏览器大量标签页、视频剪辑软件等）。

## 4. 音频问题

### 4.1 没有声音

**现象**：画面正常，但完全没声音。

**排查步骤**：

1. 在 SwitchCast 中确认**音频设备**选择的是采集卡自带的数字音频接口（名字通常和采集卡或 "USB Audio" 相关），而不是电脑的扬声器/麦克风。
2. 点击「刷新设备」重新扫描音频设备后重新选择。
3. 打开系统「设置 → 声音」，确认该音频设备没有被其他应用独占（退出其他可能占用它的软件）。
4. 检查 SwitchCast 内的音量是否被调到 0 或静音。
5. 检查 Switch 本体的音量设置：进入 Switch 的「设置 → 主机 → 音量」，确认没有调到最低。

### 4.2 音画不同步

**现象**：声音比画面快或慢，明显对不上。

**可能原因**：采集或播放链路出现延迟偏差。SwitchCast 内置了音画同步补偿，大多数情况下会自动对齐。

**排查步骤**：

1. 在「设置」中调整**音画同步偏移**选项，手动把声音对齐到画面。
2. 如果怎么调都不理想，尝试降低分辨率和帧率（减轻处理压力）。
3. 换一个 USB 口，避免与其他设备共享带宽。
4. 拔插采集卡后重新「刷新设备」并重新开始投屏。

### 4.3 有回音 / 声音重复两遍

**现象**：投屏时听到回音，或同一个游戏声音先后响两遍（间隔零点几秒）；也可能是房间里的声音被"回放"出来。

**可能原因**：按可能性从高到低有三种情况，请按顺序排查。

**① 旧版本已知缺陷（1.0.0 及之前）**

1. 特定条件下（尤其 Intel 芯片 Mac、或画面性能不足自动切换渲染模式后，再调节过音量），声音会被播放两遍形成回音。
2. **处理**：升级到最新版本（「设置 → 软件更新 → 检查更新」；或到 [GitHub Releases](https://github.com/Isaacocu/switchcast/releases) 手动下载覆盖安装，设置不受影响）。
3. 升级后若仍有问题，用下面两条继续排查。

**② 音频设备选成了 Mac 的麦克风**

1. 此时听到的是"房间声音的回放"，而不是游戏声音。
2. 到「设置」里把**音频设备**换成采集卡对应的 USB 音频设备（名字通常含采集卡名称或 "USB Audio"），不要选 "MacBook 麦克风" / 蓝牙耳机麦克风。

**③ 物理双声源**

1. 如果 HDMI 信号经过分配器，或采集卡有直通输出口接了带扬声器的显示器，会形成两个不同步的声源。
2. 去掉中转设备，或把外接设备的音量调低 / 静音。

## 5. 使用中的边界情况清单

以下情况都是已知现象，按提示处理即可，不属于故障：

- **投屏中拔插采集卡** → 先点「停止投屏」，等采集卡重新插好后点「刷新设备」，再重新开始投屏。
- **快速连续点击"开始投屏"** → 可能提示当前状态无法启动。请等待 1~2 秒再点一次。
- **同时打开两个 SwitchCast** → 后打开的窗口会因为采集卡被占用而启动失败。只保留一个窗口即可。
- **电脑休眠唤醒后画面不恢复** → 点「停止投屏」再重新「开始投屏」。
- **投屏中 Switch 关机或被拔出 HDMI** → 画面冻结或黑屏是正常现象；恢复信号后画面通常会自动恢复，若没有恢复就重启投屏。
- **合盖模式 / 外接显示器** → 笔记本合盖外接使用时功能正常；若切换显示器后窗口位置异常，把窗口拖回可见屏幕，或将应用退出重开。

## 6. 软件更新

### 6.1 检查更新

**排查步骤**：

1. 打开「设置 → 软件更新」，点击手动检查更新。
2. 应用每次启动后也会在后台自动静默检查，有新版本时会在设置中提示，无需手动操作。

### 6.2 就地更新失败

**现象**：点击下载更新后提示失败，或更新一直卡住。

**可能原因**：就地更新需要应用有权限改写自身文件。如果应用装在只读位置（比如还在 DMG 里运行）、或当前账户没有写入权限，就地更新就会失败。

**排查步骤**：

1. 确认应用已按 [1.3](#13-在-dmg-里直接运行没有拖入应用程序) 的方式安装在「应用程序」文件夹中。
2. 如果更新仍然失败，应用会自动引导你到 GitHub Release 页面——手动下载最新安装包，覆盖安装即可，你的设置不会受影响。

### 6.3 更新后首次启动又被拦截

**现象**：更新完成后，应用又被 macOS 拦截，提示"无法打开"。

**可能原因**：新下载的更新包同样带有下载隔离标记，且新版本的签名指纹与旧版不同。

**排查步骤**：

1. 右键点击应用选择「打开」放行即可，处理方式与 [1.1](#11-打开应用被-macos-拦截提示无法打开已损坏) 完全一致。
2. 如果权限弹窗也重新出现，按 [2.3](#23-应用更新后权限突然失效) 重新授权。

## 7. 仍然无法解决？反馈指南

如果按本手册排查后问题仍然存在，欢迎提交反馈，我们会尽力协助定位。

### 7.1 导出诊断报告

**排查步骤**：

1. 打开「设置 → 帮助与反馈」，点击「**导出诊断报告**」。
2. 报告会打包成一个 zip 文件，里面包含：应用运行日志、系统与设备信息、崩溃记录（如有）。
3. **诊断报告完全在本地生成，不会自动上传到任何地方**，是否对外提供完全由你决定。

### 7.2 提交 GitHub Issue

**排查步骤**：

1. 打开 [GitHub Issues](https://github.com/Isaacocu/switchcast/issues)，点击 New issue。
2. 写清楚以下内容，信息越全，定位越快：
   - **问题现象**：发生了什么、出现什么提示；
   - **复现步骤**：从打开应用开始，一步步怎么操作会触发问题；
   - **采集卡型号**：品牌 + 型号（在采集卡外壳或购买页面上可以找到）；
   - **诊断报告 zip**：把 7.1 导出的 zip 文件拖到 Issue 编辑框中上传。
3. 提交后等待回复，也可以在 Issue 里继续补充信息。
